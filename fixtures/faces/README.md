# fixtures/faces

Recorded landmark streams, replayed through the real terrain builder and the
real solver by `tests/levels/fixtures.test.ts` (SPEC §18 AC-4).

## What is in a fixture

Only what the game reads (CLAUDE.md invariant 8):

- the landmark indices listed in `src/face/landmarks.ts` → `USED_INDICES`,
  as flat `[x0, y0, x1, y1, …]` normalised image coordinates;
- the five blendshapes `jawOpen, smile, browUp, blinkL, blinkR`;
- a timestamp per frame.

**No images, no video, nobody's face.** A fixture cannot be turned back into a
picture of a person. `validateFixture()` rejects any index the game does not
itself read, so a fixture carrying extra landmarks fails the test run.

## These fixtures are synthetic — and that matters

Every file here has `"origin": "synthetic"`. They were generated by
`npm run make:fixtures`, which drives the game's own canonical Assist face
through six motions and records the result in exactly the format a real
recording would use.

SPEC §18 and PLAN.md Day 1 ask for fixtures recorded from the developer's own
face. **That has not happened**, because it needs a person at a camera. What
the synthetic set does and does not buy:

**What it does prove.** The terrain builder, the Maw hysteresis, the eyelid
hysteresis, the swept solver and the conservation invariants all run against a
*moving* face for 32 seconds at 30 Hz, 960 frames each, asserting no
tunnelling, no NaN and `saved + lost + alive == spawned` at every one of the
~3,800 physics steps per fixture. The motions are deliberately harsher than a
real head: `head-jerk` displaces the face about 0.9 FH between two tracker
frames, which is well past anything a neck can do, and is the worst case the
swept test exists for.

**What it does not prove.** Real MediaPipe output has correlated per-landmark
noise, momentary tracking loss, and asymmetries that a procedural face does
not. Those are exactly the conditions that would stress the One Euro filter
and the contour ordering hardest.

## Replacing them with real recordings

Drop-in, by design — same filenames, same schema, same tests:

1. `npm run dev`, open `/debug.html`, start the camera, calibrate.
2. Press **Record fixture**, name it, perform the motion, press **Stop and
   download**.
3. Save the file over the matching name below.

Recorded files carry `"origin": "recorded"`. Nothing else changes.

## The six motions

| File | What it is for |
|---|---|
| `neutral.json` | Sitting still. Breathing, micro-drift and natural blinks — the baseline the filter must not shimmer on. |
| `tilt.json` | Rolling the head left and right, which re-slopes every surface (SPEC §6.7). |
| `lean.json` | Leaning in and back, which scales the whole world (SPEC §6.7). |
| `brows.json` | Repeated eyebrow raises, fast enough to trigger the flick (SPEC §6.5). |
| `mouth-laugh.json` | Ten seconds of slow open/close for the Maw hysteresis, then real laughing: a smile with the jaw bouncing at ~5 Hz (SPEC §6.8). |
| `head-jerk.json` | Violent flinches with a gasp riding along, for the quake (SPEC §6.6) and the swept test. |
